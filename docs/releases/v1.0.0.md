# Captain Compose 1.0.0

Captain Compose receives MQTT deployment requests and manages long-running Docker
Compose workloads on one Docker host. This is the first stable packaged release.

## What is included

- Native binaries for Linux, macOS and Windows, each for amd64 and arm64.
- SHA-256 checksums and GitHub build attestations for release assets.
- A version-pinned online/offline installer and Linux/systemd provisioning tool.
- Durable deployment state and MQTT inbox/outbox, explicit input limits, verified
  TLS, per-request event correlation and documented crash-recovery semantics.
- Configuration examples, license, changelog and operational documentation.

## Install

Download the archive for your system from the GitHub release, verify its checksum
against `checksums.txt`, and optionally verify its GitHub build attestation:

```bash
gh attestation verify captain-compose_1.0.0_linux_amd64.tar.gz --repo Glacius-Labs/Captain-Compose
tar -xzf captain-compose_1.0.0_linux_amd64.tar.gz
bash scripts/install.sh --version 1.0.0 --prefix "$HOME/.local/bin"
captain-compose-mqtt --version
```

The installer can use a directory of previously downloaded release assets via
`--archive-dir`. On Windows, verify using `Get-FileHash -Algorithm SHA256`, extract
the ZIP and run `captain-compose-mqtt.exe`.

## Runtime host and build system

The release workflow builds on a GitHub-hosted Ubuntu 24.04 runner using the exact Go
toolchain in `go.mod`; cross-compilation produces all six native binaries. No custom
build-container base image is required.

The **runtime host** is the machine that actually runs the agent and its managed
workloads. Linux with Docker Engine and the Compose plugin is the supported
production model; Ubuntu Server 24.04 LTS is the reference base, and it can run on a
physical server, VM or edge device. macOS and Windows
binaries support development with Docker Desktop's Linux engine. The MQTT broker
can run elsewhere on your network. Installing the agent does not create that server,
install Docker, issue certificates or choose which applications to deploy.

Ubuntu 24.04 has standard security maintenance through May 2029 and is supported by
Docker Engine's Ubuntu installation path. See [Ubuntu's release cycle](https://ubuntu.com/about/release-cycle)
and [Docker's installation guide](https://docs.docker.com/engine/install/ubuntu/).

## Migration and operating boundaries

This release changes the untagged prototype protocol and project ownership model.
Add UUID request IDs and migrate workloads deliberately to `cc-<name>` projects.
Back up data and recover existing Compose manifests before replacing the prototype.
See [protocol and migration](../protocol.md) and [operations](../operations.md).

Only trusted administrators may publish deployment commands: Docker access grants
host-level authority. Provision an authenticated TLS broker with exact-topic ACLs,
durable sessions and the documented packet/queue limits. Protect and back up agent
state and workload data. A successful release pipeline is not acceptance of an
unspecified production machine or its credentials.

Compose operations may be reapplied after a crash between Docker mutation and
result persistence. Application side effects must therefore be idempotent. Removal
preserves volumes; there is no automatic data deletion or rollback of partial updates.
